# Решения по архитектуре Country Search

## 1. Отмена устаревших запросов

`src/model/createSearchController.ts` отделяет управление поиском от DOM.
`setQuery()` при **каждом** изменении поля сначала вызывает `cancelPendingWork()`:

1. Снимает владение предыдущим запросом и вызывает его `AbortController.abort()`.
2. Отменяет ожидающий вызов debounce.
3. Очищает результаты и ошибку сменой состояния.
4. Для пустого текста публикует `idle`, иначе планирует новый поиск.

Отмена происходит до ожидания debounce, а не при запуске следующего запроса.
Иначе старый ответ мог бы отобразиться во время этой паузы под уже новым текстом.
Вызов `abort()` проходит через API-обёртку до сигнала настоящего `fetch`.
Это отменяет сетевое ожидание и чтение тела ответа, а не просто скрывает результат.
Один флаг актуальности не освобождал бы сетевые ресурсы и не соответствовал бы задаче.

После `await` контроллер дополнительно проверяет владельца запроса и сигнал.
Эта проверка защищает от уже завершившихся операций и не заменяет `abort()`.
Старый `catch` или `finally` не может перезаписать состояние нового поиска:
обновления разрешены только текущему владельцу. `finally` не публикует состояние
загрузки, а только очищает ссылку на свой запрос.

### Отмена и таймаут — разные причины

`src/api/searchCountries.ts` вручную связывает два источника отмены в один
внутренний `AbortController` — эквивалент `AbortSignal.any`:

- отмена внешнего сигнала передаёт его исходный `signal.reason` (`AbortError`);
- таймер через 10 секунд вызывает `abort(new DOMException(..., 'TimeoutError'))`.

Уже отменённый внешний сигнал обрабатывается до `fetch`. Таймер остаётся активным
до окончания `response.json()`, так что зависшее чтение тела тоже ограничено.
`finally` всегда очищает таймер и удаляет слушатель внешнего сигнала.
Ручная композиция не требует наличия `AbortSignal.any` и позволяет проверять
таймаут стандартными fake timers, без ожидания десяти реальных секунд.

В `src/model/classifySearchError.ts`:

| Причина              | Результат                                                  |
| -------------------- | ---------------------------------------------------------- |
| `AbortError`         | Без сообщения и без кнопки повтора                         |
| `TimeoutError`       | Сообщение о таймауте, повтор разрешён                      |
| `HttpError`          | Сообщение с HTTP-статусом, повтор разрешён                 |
| `TypeError` от fetch | Сообщение о возможной проблеме соединения, повтор разрешён |
| Неизвестная ошибка   | Общее безопасное сообщение, повтор разрешён                |

`TypeError` рассматривается в контексте fetch: сама по себе эта категория не
доказывает отсутствие интернета. Текст ошибки предлагает проверить соединение,
но не утверждает, что это единственно возможная причина.

HTTP 404 вообще не попадает в классификатор: API-обёртка возвращает `[]`.
Остальные неуспешные статусы проверяются через `response.ok` и превращаются
в `HttpError`, потому что сам fetch не отклоняет промис при HTTP 500.

`retry()` использует последний сохранённый, обрезанный по краям запрос,
отменяет отложенную работу и запускает поиск сразу. Для пустого запроса запросов нет.

## 2. Почему debounce — 300 мс

`src/utils/debounce.ts` хранит один таймер на экземпляр функции. Повторный вызов
сбрасывает таймер; в итоге используются аргументы последнего вызова.
`cancel()` нужен для очистки поля, немедленного повтора и освобождения ресурсов.

300 мс — компромисс: небольшая пауза объединяет быстрый набор нескольких символов,
но не заставляет ждать секунды после окончания ввода. Это исходная настройка,
а не универсальная оптимальная константа; контроллер позволяет изменить её
через `debounceMs`.

- Без debounce почти каждый символ вызывал бы запрос, который затем пришлось бы
  отменять. Это лишние обращения к публичному API и мигание загрузки.
- При задержке в 1–2 секунды поиск воспринимался бы медленным даже при быстрой сети.
- Debounce сокращает частоту запросов, но сам по себе не решает гонку ответов.

## 3. Модель данных и сложность

`RawCountry` в `src/model/country.ts` описывает используемую часть ответа
countries.dev: название и столица — строки, языки и валюты — массивы объектов.
`Country` — отдельная модель карточки и деталей.

`src/model/mapCountryResponse.ts` — чистая функция:

- не обращается к сети, DOM, времени или хранилищу;
- создаёт новые массивы языков, валют и границ;
- не меняет входной объект и не отдаёт его массивы для изменения UI;
- сохраняет нулевые числа; отсутствующие население и площадь обозначает `null`;
- использует доступные SVG/PNG и текстовый флаг;
- составляет короткое описание только из имени, региона и столицы.

API не предоставляет энциклопедическое описание, поэтому приложение не выдумывает
его и не выполняет дополнительный сетевой запрос.

Для одной страны обозначим количества языков, валют и границ как `L`, `C`, `B`.
При условно ограниченной длине строк время и дополнительная память маппинга —
**O(L + C + B)**: каждый массив проходится или копируется один раз.
Если учитывать длины строк, добавляется `S` — суммарное количество символов
в создаваемых строках: **O(L + C + B + S)** по времени и памяти.
Для списка стран стоимость суммируется по всем странам.
Постоянное число скалярных полей обрабатывается за O(1).

Кэш, дедупликация и история не реализованы: это необязательный бонус.
Текущая версия не хранит ответы между поисками. `debounce` использует O(1) таймеров
и хранит аргументы только одного ожидающего вызова.

## 4. Принципы чистого кода

| Принцип                    | Конкретное применение                                                                                                                                                 |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Разделение ответственности | `searchCountries` занимается HTTP и ограничением времени, `mapCountryResponse` — преобразованием, `createSearchController` — жизненным циклом поиска, `src/ui/` — DOM |
| Чистые функции             | `mapCountryResponse`, `classifySearchError` проверяются на обычных объектах без браузера и сети                                                                       |
| Инъекция зависимости       | `createSearchController({ search })` позволяет подменять сетевой слой в модульных тестах                                                                              |
| Явные состояния и типы     | `SearchState` и `SearchError` — discriminated unions; результат доступен только в `success`, ошибка — в `error`                                                       |
| Минимизация повторений     | `src/ui/dom.ts`: типизированное создание элементов, форматирование чисел и строки фактов                                                                              |
| Безопасный текст           | `element()` использует `textContent`; значения API не интерпретируются как HTML                                                                                       |
| Освобождение ресурсов      | `finally` в API очищает таймер и слушатель; `dispose()` контроллера отменяет запрос и debounce                                                                        |
| Небольшие компоненты       | Карточка, детали в native `dialog` и приложение вынесены в отдельные функции                                                                                          |

## 5. Проверки и TDD

Тесты находятся в `tests/`, выполняются Vitest в Node без реальной сети.
Задержки проверяются fake timers; `fetch` подменяется моками.
Тесты изолированы: таймеры, глобальные моки и контроллеры очищаются после теста.
Это соответствует FIRST: быстрые, независимые, повторяемые, самопроверяемые тесты,
написанные до реализации обязательных функций.
