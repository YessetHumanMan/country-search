# Деплой и сдача

## Текущий статус

- Приватный репозиторий: https://github.com/YessetHumanMan/country-search
- Деплой: https://yessethumanman-country-search.netlify.app
- PR без мержа: https://github.com/YessetHumanMan/country-search/pull/1

`main` содержит только README и `.gitignore`, приложение находится в ветке
`country-search`. GitHub Pages недоступен на текущем тарифе для приватного
репозитория, поэтому статика опубликована на Netlify. Автоматическая связь
Netlify с GitHub не настроена: обновление деплоя выполняется через CLI.

Проходят lint, проверка форматирования, 72 модульных/интеграционных теста и сборка.
В headless Chrome **на публичном URL деплоя** проверены реальный запрос к
countries.dev, детали страны и закрытие через Escape, очистка поля, загрузка,
404, HTTP 500, сетевая ошибка и повтор последнего запроса, таймаут, отмена старого
запроса с `net::ERR_ABORTED`, отсутствие устаревшего результата и горизонтальной
прокрутки на ширине 390 px. Ошибки и задержки в этих браузерных проверках
моделировались перехватом сетевых запросов Playwright; обычный успешный поиск
также проверен с настоящим API. Скриншоты реальных результатов — в `docs/screenshots/`.

Браузерная smoke-проверка запускалась отдельно, в `npm test` она не входит;
модульные тесты не зависят от установленного браузера.

## 1. Создать приватный репозиторий

На GitHub создайте **пустой приватный** репозиторий без автоматического README,
лицензии и `.gitignore`. Не используйте force push для существующего репозитория.

Из папки проекта, заменив OWNER и REPOSITORY:

```sh
git remote add origin git@github.com:OWNER/REPOSITORY.git
git push -u origin main
git push -u origin country-search
```

Если SSH не настроен, используйте HTTPS-адрес репозитория. `pre-push` запускает
тесты текущего рабочего дерева; перед отправкой убедитесь, что вы на зелёной
вершине `country-search`. Не выполняйте squash/rebase, уничтожающий пары TDD-коммитов.

## 2. Включить GitHub Pages

**Важно:** GitHub Pages для приватного репозитория доступен не на всех тарифах.
Проверьте возможности своего аккаунта. Не делайте репозиторий публичным в обход
требования задания. Если тариф не подходит, используйте альтернативный статический
хостинг, описанный ниже.

1. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Проверьте, что environment `github-pages` разрешает деплой ветки `country-search`.
   Если политика окружения разрешает только `main`, добавьте нужную ветку.
3. В **Settings → Secrets and variables → Actions → Variables** установите
   `ENABLE_GITHUB_PAGES=true` только если Pages доступен и настроен. По умолчанию
   job `deploy` пропускается, а проверки и сборка выполняются всегда.
4. Workflow `.github/workflows/deploy.yml` запускается при push в `country-search`.
   Дождитесь успешных jobs `build` и `deploy`; прежний запуск можно повторить через
   **Actions → Re-run jobs**.
5. Откройте URL из environment `github-pages` и проверьте приложение.

Workflow сначала выполняет `npm ci`, lint, проверку форматирования, тесты и сборку.
В артефакт попадают **только** `index.html`, `styles.css` и `dist/`, не весь репозиторий.
Все URL приложения относительные: оно работает и в подпапке `/<repository>/`.

`workflow_dispatch` может отсутствовать в интерфейсе, пока workflow не находится
в default branch. Для этого задания достаточно запуска по push и повтора уже
существующего запуска: переносить приложение в `main` не нужно.

### Netlify — текущий хостинг

Для обновления сайта после изменений:

```sh
npm ci
npm run lint
npm test
npm run build:site
netlify login
netlify link --id f1a9468a-2959-4027-99dd-d46ec26d8606
netlify deploy --prod --no-build --dir _site
```

Netlify CLI должен быть установлен, а пользователь — иметь доступ к команде
`Yesset_rsschool`. `netlify.toml` задаёт команду сборки и папку публикации.
`build:site` пересоздаёт `_site` из разрешённых файлов; `.netlify` и `_site`
игнорируются Git. При ручной загрузке на другой статический хостинг загружайте
содержимое `_site`, а не корень репозитория:

```text
index.html
styles.css
dist/
  main.js
  api/...
  model/...
  ui/...
  utils/...
```

Не загружайте `node_modules`, `.git` и файлы окружения.
Backend и прокси не нужны: браузер обращается к countries.dev напрямую.

## 3. Проверить деплой

Используйте чек-лист `.github/pull_request_template.md`. В DevTools:

- Включите Slow 3G/другой throttling и начните новый запрос до завершения старого.
  Запрос должен отмениться уже при новом вводе, до запуска следующего поиска.
- Для 404 попробуйте заведомо несуществующее название.
- Для сетевой ошибки включите Offline, введите новый запрос, дождитесь ошибки,
  верните Online и нажмите «Повторить». Должен уйти именно последний запрос.
- Для таймаута используйте очень медленное соединение: ошибка появляется примерно
  через 10 секунд. Не путайте это с собственной отменой при вводе.
- Проверьте детали, клавиатурную навигацию, Escape и узкий экран.

Проверьте, что в Network запросы идут к `https://countries.dev/name/...`, а не через
чужой backend. Изображения флагов загружаются с flagcdn.com; при ошибке есть
текстовый флаг. Google Fonts необязателен: при его недоступности используется
системный шрифт.

## 4. Открыть Pull Request

Создайте PR **из `country-search` в `main`**, не мержите.
Скопируйте `.github/pull_request_template.md` в описание вручную: GitHub обычно
ищет шаблон в default branch, а `main` по заданию остаётся минимальным.

Заполните:

- ссылку на задание, скриншот, дату и срок сдачи;
- реальный URL деплоя (не localhost);
- самооценку по выполненным критериям;
- полный URL `DESIGN.md` в ветке `country-search`;
- подтверждение пар TDD-коммитов и отдельного коммита гонки;
- только действительно пройденные на деплое пункты чек-листа.

Затем отправьте URL PR в **RS App → Cross-Check: Submit**.
